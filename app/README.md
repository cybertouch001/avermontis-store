# AVERMONTIS native Android app (v3.0.0)

A real native Android app (Capacitor 7, Android System WebView). It is not a Trusted Web Activity or Custom Tab, so
no browser bar or Chrome UI ever shows. The app screens (HTML/CSS/JS, fonts, product images) ship INSIDE the APK and
open instantly, even offline. The store data (catalogue, accounts, bag pricing, orders, Cash on Delivery, tracking)
comes live from https://avermontis.sites.tab.bot over HTTPS, using a bearer token.

## Layout
- `www/`: generated by `tools/bundle_web.py` from the store repo's `site/_pages/app.html` and `site/assets/m/*`
  (the same app.js as the web /app; it detects the native shell).
- `android/`: the native project. Package `bot.tab.sites.avermontis.twa`, versionCode 3, versionName 3.0.0, min SDK 23,
  target SDK 35.
- `tools/make_native_res.py`: launcher icons, splash (obsidian + gold A), and the notification icon.
- `capacitor.config.json`: splash, status bar and notification settings.

## Native features
- Splash: the Android 12+ system splash (obsidian with the gold A), or a full splash image on older phones. The app
  hides it once it's ready.
- Status bar and navigation bar are obsidian with light icons. Content stays below the system bars.
- Android back button: closes an open sheet first, then goes back through the app's screens, then exits from Home.
- Links to policies, invoices, the website and mail open outside the app (browser or mail app).
- Skin diary camera: the CAMERA permission plus the WebView file chooser. Photos stay on the phone (IndexedDB).
- Ritual reminders: @capacitor/local-notifications, scheduled with Android's alarm service. They arrive even when
  the app is closed and are re-queued after a reboot. The next 30 days are queued and re-queued on every open, and
  today's nudge is skipped once that ritual is checked off. The timing is inexact (Android may delay a few minutes)
  because exact-alarm permission is reserved for alarm and calendar apps on Play.

## Build
    npm install
    python3 tools/bundle_web.py      # AVM_SITE=/path/to/store/site if not ../src/site
    npx cap sync android
    cd android && ./gradlew assembleRelease bundleRelease     # needs JDK 21 + Android SDK 35

Release signing reads a properties file kept outside this tree (env `AVM_KEYSTORE_PROPS`) with
storeFile, storePassword, keyAlias and keyPassword. Use the SAME keystore as v1/v2 (alias `avermontis`, cert SHA-256
BD:E6:E4:EE:37:40:CF:0E:62:C6:1A:30:C6:8E:31:B7:B6:CC:E4:BE:3D:D4:61:0B:EF:3D:63:C3:39:C4:F7:D3), or phones won't
accept the update. No keystore is included here.

## Server side (store repo `site/_worker.js`)
- `APP_ORIGINS = ['https://localhost', 'capacitor://localhost']`: CORS for /api/* from the app only.
- Sign-up and sign-in from the app return `token` in the JSON body. The app sends it back as `Authorization: Bearer`
  for customer sessions only; admin access is never available with a bearer token. The website keeps its HttpOnly
  cookies and never sees a token.
- `/download` page plus `/download/avermontis.apk` (served from `/_dl/avermontis.apk` with the APK content type).


## v4.0.0 (versionCode 4)
- Same package and signing key; installs over v1-v3 as an update.
- Launcher icons are activity-aliases of `AppActivity`: `.MainActivity` (default AVR icon, keeps the old component name so home-screen shortcuts survive), `.IconAvrGold`, `.IconAvrGreen`, `.IconClassic`. The `AvmNative` plugin (`AvmNativePlugin.java`) switches them (`setIcon`/`getIcon`) and opens Google Scene Viewer for "View in your room" (`sceneViewer`).
- The app reads the owner's live look (colours, fonts, light/dark, home order, banners, store name, features) from `/api/config` at launch and on resume, caches it, and falls back to the built-in look offline.
- AR files load from the live site (`/assets/ar/`, served with CORS) so the APK stays small; the camera features need the CAMERA permission the app already has.
- Build: `AVM_SITE=../store/site python3 tools/bundle_web.py && npx cap sync android && cd android && ./gradlew assembleRelease bundleRelease` (signing properties are read from a file OUTSIDE this tree, see app/build.gradle).
